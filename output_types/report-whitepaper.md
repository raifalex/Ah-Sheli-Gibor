# Output Type: Whitepaper

Technical / policy / industry whitepaper. Long-form, structured, evidence-heavy. Authoritative voice. Used to establish thought leadership or to inform policy.

## When this output type is right

- **Technical whitepaper** — explaining a new technology / architecture / approach
- **Policy whitepaper** — input to regulatory body (e.g., INCD, ISA, Ministry of Health)
- **Industry analysis whitepaper** — sector study with recommendations
- **Vendor whitepaper** — explaining a product's technical foundation to enterprise buyers
- **Research whitepaper** — adjacent to academic paper but published outside peer review

## Length

12–40 pages typical. Most whitepapers land at 18–25.

## Structural template

### Cover + abstract (~1 page)
- Title (Hebrew + English subtitle)
- Authors + affiliations
- Date + version
- Abstract (200–400 words) summarizing problem, approach, findings

### Executive summary (~1–2 pages)
TL;DR for executives. Key findings + recommendations.

### Introduction (~2–4 pages)
- Problem context — why this whitepaper exists
- Prior work — what's been said before, what's been done
- This whitepaper's contribution

### Background / state of the art (~3–6 pages)
- Technical background sufficient for an informed reader
- Existing approaches and their limits
- Glossary of terms used

### The approach / proposal / argument (~5–15 pages)
- The technical / policy / strategic proposal
- Detailed explanation with diagrams (referenced)
- Worked examples
- Trade-offs and design choices

### Evaluation / case studies (~3–6 pages)
- Evidence supporting the proposal
- Case studies / pilots
- Quantitative results

### Recommendations (~1–3 pages)
- Actionable recommendations per stakeholder
- Implementation roadmap

### References
Full citation list per relevant style (technical: IEEE / Chicago; policy: Israeli regulatory citation).

## Hebrew-specific conventions

- **Bilingual abstract** standard
- **Technical terms** with first-use definition (Hebrew + English in parens)
- **Smikhut-heavy** for compound technical terms
- **Figures + tables** labeled bilingually
- **Citation format** consistent throughout
- **No filler words**; formal-academic register

## Persona pairings

| Whitepaper type | Best persona |
|---|---|
| Technical / engineering | **איתמר** (patient depth) or **יואל** (engineering mode) |
| Policy / regulatory | **שירה** (formal-classical) or **דנה** (sharp positioning) |
| Industry analysis | **איתמר** |
| Vendor / product | **יואל** (mission-frame) |

## Validation gates

- [ ] Bilingual abstract present
- [ ] Executive summary captures full argument
- [ ] Prior work cited honestly
- [ ] Diagrams referenced clearly
- [ ] At least one worked example or case study
- [ ] Recommendations actionable
- [ ] Citations consistent
- [ ] Hebrew grammar formal-academic throughout
- [ ] Persona voice authoritative

## Related output types

- For peer-reviewed academic depth: `research-paper`
- For internal decision: `report-executive`
- For market focus: `report-business`
